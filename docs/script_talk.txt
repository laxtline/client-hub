-------------------------------------------------------------------------------
 (A) SHORT INTRO — ~30 seconds (memorize this)
-------------------------------------------------------------------------------
Hello Sir/Ma'am,

My project name is ClientHub — an AI-Powered Agency Client & Project
Management Portal. It is a full-stack web application that helps a freelance
agency manage its clients, projects, and tasks; send invoices and collect
online payments; and automatically share an AI-generated weekly progress
report with each client.

I built it using a React frontend, a Node.js and Express backend, a
PostgreSQL database with the Prisma ORM, Socket.io for real-time updates, and
the Groq AI API — with a focus on clean design, security, and scalability.

Through this project I gained hands-on experience in full-stack development,
REST API design, database modeling, authentication, third-party integrations,
testing, and deployment.

Thank you. I would be happy to explain any feature, module, or technical
implementation in detail.

-------------------------------------------------------------------------------
 (B) LONGER WALKTHROUGH — if they ask "explain your project"
-------------------------------------------------------------------------------
PROBLEM IT SOLVES:
Freelance agencies use many separate tools — spreadsheets for clients, one app
for tasks, email for updates, and another tool for invoices. Clients have no
clear view of progress, and writing weekly status updates by hand is slow.
ClientHub brings all of this into one role-aware portal and automates the
status reporting using AI.

WHO USES IT (three roles, with role-based access control):
- Admin        : full control over clients, projects, tasks, and invoices.
- Team Member  : works on tasks, logs hours, comments.
- Client       : sees only their own projects, progress, invoices, and the AI
                 weekly summary, and can pay online.

MAIN FEATURES:
- Secure authentication using JWT tokens and bcrypt-hashed passwords.
- Client and project management with an auto-calculated progress percentage.
- A drag-and-drop Kanban task board (To Do, In Progress, Review, Done) with
  comments, time tracking, and an activity log.
- Invoicing with PDF export and online payments through Razorpay, where the
  payment is confirmed on the server using a verified webhook signature.
- Real-time notifications with Socket.io, plus an email fallback.
- Analytics dashboards built with Recharts.
- The main highlight: an AI weekly progress summary. The system collects a
  project's activity for the week and asks the Groq API to write a short,
  client-friendly summary and a risk flag — on-track, at-risk, or delayed. If
  the AI is ever unavailable, it falls back to an automatic template, so the
  app never breaks.

TECHNOLOGY STACK:
- Frontend : React, Vite, Tailwind CSS, Recharts, React Router.
- Backend  : Node.js, Express, Prisma ORM, PostgreSQL.
- Realtime : Socket.io.
- Services : Groq AI API, Razorpay, ImageKit, Nodemailer.
- Quality  : Vitest tests (44 passing), ESLint and Prettier with zero warnings,
             GitHub Actions CI, and Docker with docker-compose for one-command
             setup.

WHAT I LEARNED:
Designing a normalized database with nine related tables, building a clean REST
API with a separate services layer, securing routes with role-based access and
per-client data isolation, integrating real third-party APIs, writing automated
tests, and deploying the full stack. I also learned to handle failure
gracefully — the AI fallback is a good example of production-safe thinking.

Thank you. I can demonstrate any module live or walk through the code.

-------------------------------------------------------------------------------
 QUICK Q&A — likely questions and short answers
-------------------------------------------------------------------------------
Q: Why did you choose this tech stack?
A: React and Node share one language (JavaScript), Prisma makes PostgreSQL safe
   and easy to query with type-safe generated methods, and Socket.io gives
   simple real-time updates.

Q: Why PostgreSQL and not MongoDB?
A: The data is highly relational — a client has projects, a project has tasks
   and invoices, an invoice has payments. Foreign keys and cascade deletes keep
   that consistent at the database level, which a document store would leave to
   my application code.

Q: How is it secure?
A: Passwords are bcrypt-hashed. Sessions use signed JWTs verified on every
   request, with the algorithm pinned so a differently-signed token is rejected.
   Roles are enforced on the backend, not just hidden in the UI. Input is
   validated with Zod. Helmet sets security headers, and login is rate-limited
   to ten attempts per fifteen minutes. And payments are confirmed only after
   verifying the gateway's HMAC webhook signature.

Q: What is "tenant isolation"? Can one client see another client's data?
A: No. Beyond role checks, every endpoint that returns client data looks up the
   caller's own client record from their user id and filters by it. If a client
   requests another client's project by id, the server returns 403 — even though
   their token is completely valid. That check lives on the server, so bypassing
   the UI does not help.

Q: What is the most challenging / unique part?
A: The AI progress summary — aggregating real project data, prompting the
   Groq API for a summary plus a risk flag in strict JSON, validating the
   response, and adding a deterministic fallback so the feature is reliable even
   if the AI call fails or returns something unexpected.

Q: What happens if the AI or the payment gateway is down?
A: Nothing breaks. Every external integration is optional. The AI falls back to
   a computed summary and the UI labels it as a fallback. Payments return a
   clear 503 instead of a crash. Uploads and email fail soft and log. The app
   runs with only a database URL and a JWT secret configured.

Q: How did you make it fast?
A: The biggest win was route-level code splitting. Originally every visitor
   downloaded the charting library and the drag-and-drop library just to see the
   login page — about 748 kB. With React.lazy per route and a dynamic import for
   the socket client, the first load is now about 233 kB, and heavy libraries
   arrive only on the pages that use them. I also debounced the client search so
   typing sends one request instead of one per keystroke, and enabled gzip.

Q: Is it tested and deployable?
A: Yes — 44 automated tests pass, covering the pure calculations, the auth
   controller, the RBAC middleware, the central error handler, and the webhook
   signature verification. Linting and CI run on every push, and it launches
   with a single "docker compose up" or deploys free on Vercel, Render and Neon.

Q: What would you add next, given more time?
A: Refresh-token rotation, database-backed password-reset tokens instead of the
   current in-memory ones, a Redis adapter so Socket.io can scale to multiple
   server instances, and end-to-end browser tests with Playwright.

Q: Did you write all of it yourself?
A: Yes, and I can walk through any file. (Be honest about tools you used — being
   able to explain and defend every design decision is what actually matters.)
