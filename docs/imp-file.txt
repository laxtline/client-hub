===============================================================================
 ClientHub — IMPORTANT FILES & FOLDERS FOR DEPLOYMENT
===============================================================================
 What this file is: a complete inventory of every file and folder in this
 project, split into what is REQUIRED to deploy and what is not.

 Short answer: push the WHOLE repository to GitHub. Render and Vercel each
 build only the sub-folder you point them at (server/ and client/), so the
 extra files cost you nothing. This list exists so you know what must never
 be deleted, and so you can answer "what does this file do?" in a viva.

===============================================================================
 SECTION 1 — THE 6 FILES THAT DEPLOYMENT ACTUALLY DEPENDS ON
===============================================================================
 If any ONE of these is missing or wrong, the deploy fails. Learn these six.

  1. server/package.json
     Declares every backend dependency, the start script, AND two things that
     are easy to miss:
       - "postinstall": "prisma generate"  -> the Prisma client is generated
         automatically during npm install, so Render needs no extra command.
       - "prisma": { "schema": "src/prisma/schema.prisma" }  -> tells Prisma
         where the schema lives, because it is NOT in the default location.

  2. server/src/prisma/schema.prisma
     The database blueprint. `npx prisma db push` reads this file and creates
     the tables in Neon. Every model lives here (User, Client, Project, Task,
     TaskComment, Invoice, Payment, Notification, AISummary, PasswordResetToken).

  3. server/src/server.js
     The backend entry point. This is literally the Render Start Command
     (`node src/server.js`). It boots Express and attaches Socket.io.

  4. client/package.json
     Frontend dependencies and the "build" script Vercel runs.

  5. client/index.html
     Vite's HTML entry point. Vite will not build without it. It also holds the
     inline dark-mode script that runs before React mounts (no white flash).

  6. client/vite.config.js
     Build configuration — output settings, manual vendor chunks, and the
     Vitest config. Controls how the production bundle is split.

 SECTION 6 — NEVER COMMIT THESE
===============================================================================
 All of these are already in .gitignore. Just never force-add them.

   .env                  real secrets — DATABASE_URL, JWT_SECRET, API keys
   server/.env
   client/.env
   node_modules/         reinstalled from package-lock.json on every build
   dist/                 build output, regenerated every deploy
   DEMO_LOGINS.txt       kept outside the repository on purpose
   *.log

 If you ever accidentally commit a .env: rotate every key in it immediately.
 Removing the file in a later commit does NOT remove it from git history.

 SECTION 7 — ENVIRONMENT VARIABLES (not files, but deployment fails without them)
===============================================================================

 ON RENDER (backend) — required:
   NODE_ENV                = production
   PORT                    = 5000
   DATABASE_URL            = <Neon connection string, ends with ?sslmode=require>
   JWT_SECRET              = <32+ random characters — short = boot failure>
   JWT_EXPIRES_IN          = 7d
   CLIENT_URL              = <your exact Vercel URL, NO trailing slash>
   CRON_TIMEZONE           = Asia/Kolkata

 ON RENDER (backend) — optional, features degrade gracefully without them:
   GROQ_API_KEY, GROQ_MODEL
   RAZORPAY_KEY_ID, RAZORPAY_KEY_SECRET, RAZORPAY_WEBHOOK_SECRET
   IMAGEKIT_PUBLIC_KEY, IMAGEKIT_PRIVATE_KEY, IMAGEKIT_URL_ENDPOINT
   SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM

 ON VERCEL (frontend) — all required, and they are baked in AT BUILD TIME:
   VITE_API_URL            = https://<your-api>.onrender.com/api      (WITH /api)
   VITE_SOCKET_URL         = https://<your-api>.onrender.com          (NO /api)
   VITE_RAZORPAY_KEY_ID    = rzp_test_xxxxxxxx

 The /api difference between those first two is the single most common
 deployment mistake. Changing any VITE_* value requires a REBUILD — editing it
 in the dashboard alone does nothing.

 SECTION 8 — DEPLOY SETTINGS CHEAT SHEET
===============================================================================

 RENDER (backend)
   Root Directory   : server
   Runtime          : Node          (not Docker)
   Build Command    : npm install && npx prisma db push
   Start Command    : node src/server.js
   Instance Type    : Free
   One-time, after the first successful deploy:
       open the Shell tab and run  npm run seed

 VERCEL (frontend)
   Framework Preset : Vite
   Root Directory   : client
   Build Command    : npm run build     (auto-detected)
   Output Directory : dist              (auto-detected)

 NEON (database)
   Create the project, copy the connection string into DATABASE_URL on Render.
   Nothing else to configure — `prisma db push` creates every table.
